# Модель данных v0.4

> Следует из `concept.md` v1.10. Событийный принцип: итоги считаются запросами.
> Все таблицы имеют `id` (PK) и, где уместно, `created_at`.
> **Аудит:** все событийные таблицы (события партий, яйцо, корм, деньги) дополнительно
> содержат `created_by` → `users.id` — кто внёс запись.

## Пользователи

| Таблица | Поля | Примечания |
|---|---|---|
| `users` | username, password_hash, role (`admin` / `user`), is_active, created_at | Управление пользователями — через UI админом (§6 концепции). Отключённый (`is_active=false`) не может войти; его записи сохраняются |

## Справочники (редактируются в UI)

| Таблица | Поля | Назначение |
|---|---|---|
| `places` | name, kind (`broiler_module` / `lay_house`), note | Места содержания (§4.1): 2 бройлерных модуля + курятник несушек |
| `feed_categories` | name | Категории корма: старт, рост, финиш, несушка + свои |
| `feed_brands` | name | Производители корма (для сравнения конверсии) |
| `vendors` | name, note, types (JSON: цыплята/корм/лекарства/прочее — можно несколько) | Продавцы. Теги привязаны к задачам и проверяются жёстко: в операции доступен только продавец с нужным тегом |
| `buyers` | name, phone, address | Покупатели продукции: бройлер, яйцо |
| `product_types` | name | Виды мясной продукции: тушка, потроха, печень… — расширяемый |
| `money_categories` | name, kind (`income` / `expense`) | Категории журнала денег |

| Таблица | Поля | Примечания |
|---|---|---|
| `lay_flocks` | name, place_id → places, start_date, status | Стадо несушек (§4.2; сейчас одно) |
| `lay_flock_changes` | flock_id, date, head_delta (+/−), reason | Пополнение/выбраковка; текущее поголовье = сумма дельт |
| `egg_collections` | flock_id, date, pieces | Ежедневный сбор |
| `egg_selfuse` | flock_id, date, pieces | Расход «для себя» |
| `egg_sales` | date, dozens, price_per_ten, buyer_id → buyers (nullable), total_amount | Продажа десятками; стадо не указывается (одно стадо; при втором — миграция) |

Остаток яйца = Σсборов − Σсамопотребление − Σпродаж×10.

## Хозяйственные события

| Таблица | Поля | Примечания |
|---|---|---|
| `farm_writeoffs` | date, head_count, cause | Списание птицы без привязки к партии (§4.1, «одно обобщённое»); уменьшает общее поголовье хозяйства |

## Корм (склад)

| Таблица | Поля | Примечания |
|---|---|---|
| `feed_purchases` | date, feed_category_id, feed_brand_id, vendor_id → vendors, kg, total_cost | Приход на склад; порождает транзакцию денег |
| `feed_adjustments` | date, feed_category_id, feed_brand_id, kg_delta, comment | Инвентаризация (корректировка остатка) |

Остаток корма = Σзакупок − Σрасходов (партии + стадо несушек) + Σкорректировок
(в разрезе категория × производитель).

## Деньги

| Таблица | Поля | Примечания |
|---|---|---|
| `money_transactions` | date, money_category_id, amount, description, batch_id?, flock_id? | Единый журнал. Доход/расход определяется категорией (kind дублировать не нужно). Транзакции от событий создаются автоматически; общие расходы — вручную |

Общие расходы к партиям **не записываются** физически — доля считается
запросом (куро-дни за период), чтобы формулу можно было менять без миграций.

## Ключевые вычисляемые показатели

| Показатель | Формула (источники) |
|---|---|
| Текущее поголовье хозяйства | Σ(текущее поголовье активных партий: `head_count` − падёж − забитые) + текущее поголовье стада несушек − Σсписаний (`farm_writeoffs`) |
| Поголовье партии | `head_count` − Σпадёж − Σзабитых голов |
| Сохранность партии | (Σзабитых + Σпадежа) / `head_count` |
| Конверсия корма (FCR) | Σкг корма / привес партии. Привес = Σlive_weight − `chick_avg_weight_kg` × головы на забое; если вес цыплёнка не указан — привес по контрольным взвешиваниям; нет ни того ни другого — «нет данных» |
| Привес | по контрольным взвешиваниям между датами |
| Выход продукции | Σкг вида / Σlive_weight — суммарно и по каждому виду |
| Пересчёт живой вес ↔ продукция | живой вес = продукция / (выход, доли); обратно: продукция = живой вес × выход |
| Себестоимость кг продукции | (прямые затраты партии + доля общих) / Σкг продукции |
| Прибыль партии | Σпродаж − (прямые затраты + доля общих расходов) |

## Ограничения целостности (кратко)

- Одна активная партия на место содержания — правило по умолчанию; при попытке
  заселить вторую партию UI предупреждает, но не запрещает. Количество мест
  и одновременных партий не ограничено: рост хозяйства — добавлением записей
  в `places`, без изменений схемы.
- Соответствие тега продавца типу операции проверяется жёстко (UI + API):
  закупка корма — тег «корм», партия цыплят — тег «цыплята», и т.п.
- `batch_feedings` и `lay_feedings` списывают со склада; остаток может уйти
  в минус (с предупреждением UI), чтобы не блокировать ввод фактов.
- Даты событий партии ≥ даты закупки партии; дата продажи ≥ даты забоя.
