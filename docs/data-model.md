# Модель данных (черновик v0.1)

> Следует из `concept.md` v1.3. Событийный принцип: итоги считаются запросами.
> Все таблицы имеют `id` (PK) и, где уместно, `created_at`.
> **Аудит:** все событийные таблицы (события партий, яйцо, корм, деньги) дополнительно
> содержат `created_by` → `users.id` — кто внёс запись.

## Пользователи

| Таблица | Поля | Примечания |
|---|---|---|
| `users` | username, password_hash, role (`admin` / `user`), is_active, created_at | Управление пользователями — через UI админом. Отключённый (`is_active=false`) не может войти; его записи сохраняются |

## Справочники (редактируются в UI)

| Таблица | Поля | Назначение |
|---|---|---|
| `places` | name, kind (`broiler_module` / `lay_house`), note | Места содержания: 2 бройлерных модуля + курятник несушек |
| `feed_categories` | name | Категории корма: старт, рост, финиш, несушка + свои |
| `feed_brands` | name | Производители корма (для сравнения конверсии) |
| `vendors` | name, note, types (JSON, необязательно: цыплята/корм/лекарства/прочее — можно несколько) | Продавцы. Теги упорядочивают подсказки, не ограничивают выбор |
| `buyers` | name, phone, address | Покупатели продукции: бройлер, яйцо |
| `money_categories` | name, kind (`income` / `expense`) | Категории журнала денег |

## Бройлеры

| Таблица | Поля | Примечания |
|---|---|---|
| `broiler_batches` | code (№ партии), place_id → places, start_date, head_count, cross, vendor_id → vendors, chick_price_per_head, status (`active` / `closed`), closed_at | Паспорт партии. Закупка цыплят автоматически порождает транзакцию денег |
| `batch_mortalities` | batch_id, date, head_count, cause | Падёж |
| `batch_feedings` | batch_id, date, feed_category_id, feed_brand_id, kg | Списывает со склада |
| `batch_weighings` | batch_id, date, head_count, avg_weight_kg | Опционально |
| `batch_treatments` | batch_id, date, description, cost | Лечение/обработки |
| `batch_slaughters` | batch_id, date, head_count, live_weight_kg, product_weight_kg | Забой+разделка; допускается несколько записей (частичный забой) |
| `batch_sales` | batch_id, date, product_kg, price_per_kg, buyer_id → buyers (nullable), total_amount | Реализация по весу |

## Несушки и яйцо

| Таблица | Поля | Примечания |
|---|---|---|
| `lay_flocks` | name, place_id → places, start_date, status | Стадо несушек (сейчас одно) |
| `lay_flock_changes` | flock_id, date, head_delta (+/−), reason | Пополнение/выбраковка; текущее поголовье = сумма дельт |
| `egg_collections` | flock_id, date, pieces | Ежедневный сбор |
| `egg_selfuse` | flock_id, date, pieces | Расход «для себя» |
| `egg_sales` | date, dozens, price_per_ten, buyer_id → buyers (nullable), total_amount | Продажа десятками |

Остаток яйца = Σсборов − Σсамопотребление − Σпродаж×10.

## Корм (склад)

| Таблица | Поля | Примечания |
|---|---|---|
| `feed_purchases` | date, feed_category_id, feed_brand_id, vendor_id → vendors, kg, total_cost | Приход на склад; порождает транзакцию денег |
| `feed_adjustments` | date, feed_category_id, feed_brand_id, kg_delta, comment | Инвентаризация (корректировка остатка) |

Остаток корма = Σзакупок − Σрасходов партий + Σкорректировок (в разрезе
категория × производитель).

## Деньги

| Таблица | Поля | Примечания |
|---|---|---|
| `money_transactions` | date, kind (`income` / `expense`), money_category_id, amount, description, batch_id?, flock_id? | Единый журнал. Транзакции от событий (закупка цыплят, корм, лечение, продажи) создаются автоматически с привязкой; общие расходы — вручную без привязки |

Общие расходы к партиям **не записываются** физически — доля считается
запросом (куро-дни за период), чтобы формулу можно было менять без миграций.

## Ключевые вычисляемые показатели

| Показатель | Формула (источники) |
|---|---|
| Текущее поголовье партии | `head_count` − Σпадёж − Σзабитых голов |
| Сохранность партии | (Σзабитых голов) / `head_count` |
| Конверсия корма (FCR) | Σкг корма / (живой вес на забое − вес цыплёнка) — при наличии взвешиваний |
| Привес | по контрольным взвешиваниям между датами |
| Выход продукции | Σproduct_weight / Σlive_weight |
| Пересчёт живой вес ↔ продукция | живой вес = продукция / (выход, доли) × 100; обратно: продукция = живой вес × выход |
| Себестоимость кг | (прямые затраты партии + доля общих) / кг продукции |
| Прибыль партии | Σпродаж − затраты партии − доля общих расходов |

## Ограничения целостности (кратко)

- Одна активная партия на модуль: проверка на уровне приложения (частичный
  случай — несколько партий в одном месте — сознательно запрещён).
- `batch_feedings` списывает только существующий остаток — проверка приложения;
  нехватка допустима (уходим в «минус склада» с предупреждением), чтобы не
  блокировать ввод фактов.
- Даты событий партии ≥ даты закупки партии.
